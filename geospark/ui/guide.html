GeoSpark Guide

New here? This page walks you through everything you can do with GeoSpark in about 10 minutes.

🌎

What is GeoSpark?

GeoSpark is an open-source geospatial intelligence engine that gives AI models real spatial reasoning. Most LLMs fail at spatial tasks — they score 0% on geodesic distance and ~48% on topology checks. GeoSpark fixes this by providing ground-truth computation through a standardized protocol.

Beyond the spatial engine, GeoSpark is also a multi-agent platform with persistent memory, a tiered context database, and live data channels. Everything runs on your hardware at $0 cost.

60-second tour

Follow these five steps to experience the full stack. No Ollama needed for steps 1 and 2.

  1. Save a fact (Memory)
    Go to Memory, click Add tab, save: "Eiffel Tower is at 48.8584 N, 2.2945 E". Then query "Eiffel" in the Recall tab.
    Go to Memory →
  2. Save a mission (Context)
    Go to Context, click Save tab, the form is pre-filled with geospark://missions/example. Click Save, then Browse to see it. Click the card to drill down through L0 → L1 → L2 tiers.
    Go to Context →
  3. Classify a goal (Coordinator)
    Go to Agents, the first tab is Coordinator. Click "Classify only" with different prompts — see how each routes to a different specialist. No Ollama needed for classification.
    Go to Agents →
  4. Measure a distance (Playground)
    Go to Playground, Distance tab. Click the Paris → London preset. You'll get 343,923 m — geodesic, not Euclidean, not an LLM guess.
    Go to Playground →
  5. Fetch real data (Data)
    Go to Data, query weather for any city. No API key needed for weather (Open-Meteo is free). Air quality and fires need free API keys — see Setup tab.
    Go to Data →
Tip: The "Classify only" button on the Coordinator tab is the fastest way to understand how GeoSpark's routing works. It shows the decision without actually invoking the specialist.

Walkthrough 1: Build knowledge about a city

End-to-end: save facts + save a mission context + query both.

  1. Geocode the location
    Go to Playground, Geocode tab. Search "Melbourne CBD". Note the coordinates.
  2. Save the coordinates as a fact
    Go to Memory, Add tab, save a fact with the Melbourne coordinates you just geocoded. Tag it melbourne, cbd.
  3. Create a mission context
    Go to Context, Save tab. URI: geospark://missions/melbourne_study. Category: missions. Abstract: "Melbourne CBD study area". Tags: melbourne, study. Bounds: 144.9, -37.9, 145.1, -37.7. Save it.
  4. Query both systems
    Memory: recall "Melbourne" → see the fact. Context: query "Melbourne" → see the mission. Both systems reference the same place but from different angles (short-term vs. long-term knowledge).
🔍

Walkthrough 2: Site selection via coordinator

Requires Ollama running locally (see Setup tab).

  1. Start Ollama
    If not running: ollama serve in one terminal. Pull a model: ollama pull qwen2.5:7b.
  2. Classify the goal first
    Go to Agents, Coordinator tab. Enter "Find the best location for a pharmacy in Zurich near hospitals and schools". Click Classify only → should route to site_selector.
  3. Run the full coordinator
    Click Run. The coordinator dispatches to SiteSelector, which fetches OSM candidates, computes distance-weighted scores, and returns ranked candidates. Takes 30-60 seconds.
  4. Remember the result
    Once you see the top location, go to Memory and save it as a fact: "Best pharmacy site in Zurich: [location]". Next time you recall "Zurich pharmacy", it'll come back.
🌧

Walkthrough 3: Disaster response workflow

Combines data channels + memory + context.

  1. Check active fires
    Go to Data, Fires tab. Search "California". See real-time MODIS/VIIRS detections (requires FIRMS_MAP_KEY).
  2. Save as an episode
    Go to Memory → Add tab. Save: "3 active fires detected near Sacramento on [date]". Importance: 0.9 (high). Tags: fire, california, urgent.
  3. Create a response mission
    Go to Context → Save tab. URI: geospark://missions/california_fires_2026. Abstract: "Active wildfire response in California". Bounds: California bbox.
  4. Future recall
    Next time someone asks about California fires, both Memory (recent episodes) and Context (the mission) surface the relevant information.

Running GeoSpark locally

This is already running if you're reading this page! But for reference:

git clone https://github.com/Maz2580/geospark.git
cd geospark
python -m venv .venv
.venv/Scripts/activate              # Windows
source .venv/bin/activate           # macOS/Linux
pip install -e ".[api,intelligence]"
uvicorn geospark.api:app --reload   # Serves the UI at http://localhost:8000

Ollama for local LLM

Ollama runs LLMs on your machine. GeoSpark uses it for agent reasoning (GeoAgent, SpatialReport, SiteSelector) and the LLM gateway. Without it, those features will fail with a 502 or connection error.

  1. Install Ollama
    Download from https://ollama.com/download. Works on macOS, Windows, Linux.
  2. Start the service
    ollama serve in a terminal. Keeps running in the background on port 11434.
  3. Pull a model
    ollama pull qwen2.5:7b (about 4.7 GB, ~5 min on a fast connection). This is the default GeoSpark model.
  4. Verify
    Visit the Status page or run: curl http://localhost:11434/api/tags. You should see the list of installed models.

Free API keys for data channels

Weather (Open-Meteo) needs no key. Air Quality (OpenAQ) and Fires (NASA FIRMS) are free but require registration.

Tier 0

Open-Meteo (Weather)

No key needed. Just works.

Tier 1

OpenAQ (Air Quality)

Register at openaq.org/register. Free. Set OPENAQ_API_KEY in .env.

Tier 1

NASA FIRMS (Fires)

Register at firms.modaps.eosdis.nasa.gov/api/area/. Free. Set FIRMS_MAP_KEY in .env.

After setting keys, restart the server (the reload flag catches .env changes automatically).

Troubleshooting

502 Bad Gateway on /api/v1/llm/models
Ollama isn't running or is unreachable on port 11434. Start it with ollama serve. Or ignore the error — the LLM gateway is optional; memory, context, and data pages all work without it.
Agent runs hang or time out
Agents make real calls to Nominatim (geocoding), Overpass (OSM queries), and Ollama (reasoning). First call to Ollama is slow as the model loads into RAM (15-30s). Subsequent calls are under 5s.
"Channel unconfigured" on Data page
The corresponding API key is missing. Check the Status page — channels report their config state there.
Memory/Context recall returns nothing
Make sure you've actually saved something first. Empty store is empty. Use the Stats tab on each page to see counts.

Glossary

The key terms used across GeoSpark.

Spatial Protocol (GSP)

A standardized JSON schema for spatial queries and results. Any tool can implement GSP and plug into GeoSpark.

Spatial Reasoning Engine

The core component that performs topology, distance, CRS transforms, and geometric operations — all computed on the WGS84 ellipsoid.

Specialist Agent

An autonomous agent for a specific task: GeoAgent (general), SpatialReport (location dossiers), SiteSelector (optimal placement).

Coordinator

Meta-agent that classifies a natural language goal and routes it to the right specialist. Uses rule-based patterns and keyword matching.

Spatial Fact

Time-agnostic knowledge: "The Eiffel Tower is at 48.86 N, 2.29 E". Stored in Memory with confidence score.

Spatial Episode

Timestamped observation: "PM2.5 was 120 in Delhi on April 9". Has importance weight. Subject to compaction over time.

Contradiction

Two facts that are highly similar but claim different values — likely describing the same entity with conflicting information. Auto-detected.

GeoContext (L0/L1/L2)

L0 = 1-2 sentence abstract, always in prompts. L1 = structured outline. L2 = full data, loaded only on demand.

Hotness Score

Combined frequency + recency: sigmoid(log1p(count)) * exp(-decay * age_days). Determines which contexts are hot or cold.

Data Channel

Pluggable real-time data source. Tier 0 = free no key, Tier 1 = free with key, Tier 2 = commercial.

Flow

A DAG of spatial operations that runs as a single workflow. Can be persisted and re-run. See geospark flow list in the CLI.

MCP Server

Model Context Protocol server. GeoSpark exposes 6 spatial tools over MCP so Claude Desktop and other MCP clients can use them natively.
